## Overview
A spatial trajectory is a trace generated by a moving object within a certain spatial-temporal context and is generally represented by a series of chronologically ordered points. While trajectory data plays an important role in domains like traffic analysis, public transportation management and wildlife monitoring, accurate and complete data are usually hard to obtain due to various factors, such as weak GPS signal in certain area or low sampling rate as well as privacy concerns. 

**PaLMTo** uses simple probabilistic language models in order to complete missing parts of a trajectory. In [^2] the authors presented an approach, based on PaLMTo for generating arbitrarily large and realistic trajectories based on a given trajectory dataset. This project presents WebPaLMTo, a web-based stand-alone web-based implementation application of the approach presented in [^2].

The main idea behind the trajectory generation is:

- **Tessellate** the trajectory space into grid cells,

- **Assign** unique identifiers to each partition on the tesselated space,

- **Substitute** each trajectory point within a partition by the partition's identifier.

Once that is done, the trajectories will no longer be a set of finely granulated observations, e.g., GPS points, but rather be a sentence in the space of grid identifiers. That allows to learn a probabilistic model, as simple as N-grams, that can be used for various NLP-like tasks, such as sentence completion, but for trajectories.

### How it works
The trajectory generation process involves two main steps:

1. **Build N-gram Model**: the system processes input trajectory data, creates an overlay over the geographical region from which trajectories are sampled from, converts trajecotries into token sequence, and builds probabilistic N-gram models (bigrams and trigrams);

2. **Generate Trajectory**: using the generated N-gram models, the system creates new synthetic trajectories based on user-specified parameters.

## Features
- **Interactive Map Visualization**: view original and generated trajectories on interactive Leaflet maps
- **Heatmap Comparison**: compare trajectory density patterns between original and generated trajectories
- **Area Filtering**: filter data to a sub-area on maps and generate trajectories from filtered data
- **3D Visualization**: explore trajectories in a 3D spatial-temporal space and discover hidden patterns 
- **Cache Management**: save and reuse N-gram model to avoid reprocessing
- **Real-time Progress Tracking**: monitor generation process via Server-Sent Events (SSE)
- **Data Export**: download generateted trajectories as CSV files

## Getting Started
### Prerequisites
Before you start, ensure the following requirements are met:

#### Backend
- Python 3.8 or higher
- pip 
- pipenv 

#### Frontend
- Node.js 14.x or higher
- npm 6.x or higher

#### System 
- Minimum 4GB RAM (8GB+ recommended)
- Modern web browser

### Installation

#### 1. Clone the repository
```
git clone <repository-url>
cd PaLMTool
```

#### 2. Create and activate virtual environment
```
pipenv install
pipenv shell
```

#### 3. Install backend dependencies
```
pipenv install -r requirements.txt
```

#### 4. Set up default database
```
cd PaLMTo_App
python manage.py makemigrations
python manage.py migrate
```

#### 5. Install frontend dependencies
```
cd frontend
npm install
```

#### 6. Create environment variables
Create a `.env` file in `frontend/` directory and define the following variable:
```
REACT_APP_API_URL=http://localhost:8000
```

### Initialization
After installing all required libraries, navigate back to project root folder, then run
```
python manage.py runserver
```
The backend will be served at `http://localhost:8000`.

Open a second terminal, start frontend server by running
```
cd frontend
npm start
```
The frontend will automatically open at `http://localhost:3000`

### How to use the app
The web application follows a two-step workflow(you can skip directly to step 2):

#### Upload a trajectory file or ngram model file
1. Trajectory file must be a csv file with at least two columns:
    - `trip_id`: unique numerical identifier for reach row of trajectory
    - `geometry`: a list of cooridnate pairs formatted as `[[lon1, lat1], [lon2, lat2], ...]`(note longitude must come first)
2. Ngram model file is a custom pickle file with an extension of `.pkl`. It can be obtained after running this step. Users may refer to sample trajectory file and ngram file below the upload field. 
3. Specify **Cell Size** (in meters):
    - Smaller values = finer granularity with more cells
    - Larger values = coarser granularity with fewer cells
4. Click "Train/Load".
5. (Optional) Save the generated pickle file. If you want to save the ngram model for future use or share it with someone else, save it with a custom file name ending with .pkl.

#### Generate trajectories
1. Configure generation parameters: 
    - **Number of Trajectories** total number of synthetic trajectories to generate
    - **Generation Method**: Point-to-Point or Length-contrained
    - **Trajectory Length** (valid only for length-contrained method): number of points per trajectory
2. Click "Generate".
3. View and analyze results:
    - **Trajectory View**: side-by-side comparison of original and generated trajectories. Users may also refine the input data by filtering it with a built-in drawing tool, from which new synthetic trajectores can be generated.
    - **Heatmap View**: density comparison between original and generated data.
    - **3D View**(experimental): 3D visualization with an additional temporal dimension.  
4. Download generated trajectories as CSV files.

## API Documentation
All API endpoints are prefixed with `trajectory/`

### POST `generate/ngrams`
Genrate N-gram models from trajectory data.

**Request**
```
- Method: POST
- Content-Type: multipart/form-data
- Parameters:
    - file: CSV file containing trajectory data
    - cell_size: integer, side length of grid cells in meters
    - north, south, east, west(optional): floats for area filtering
```

**Response**
```
{
    task_id: uuid-string,
    message: string
}
```

### POST `generate/`
Generate synthetic trajectories using N-gram model.

**Request**
```
- Method: POST
- Content-type: multipart/form-data
- Parameters:
    - cache_file: string, filename of cached model
    - num_trajectories: integer, number of trajectories to generate
    - generation_method: string, either "point_to_point" or "length_constrained"
    - trajectory_len: integer, required if choosing "length_contrained"
    - delete_cache_after(optional): boolean flag
```

**Response**
```
{
    task_id: uuid_string,
    message: string
}
```

### GET `download/{filename}`
Download generated trajectory files.

### GET `3d-view/`
Visualize demo trajectories in a 3D space and experiment with interactive filtering in real-time.

### POST `rename-cache/`
Rename a cached N-gram model file.

**Request**
```
- Method: POST
- Parameters:
    - old_name: string, current filename
    - name_name: string, new filename (must end with ".pkl")
```

### POST `get-stats-from-cache/`
Retrieve statistics from a cached model.

**Request**
```
- Method: POST
- Parameters: 
    - cache_file: string, filename of cached N-gram model
```

## Troubleshooting

1. "CSRF cookie not set" error
- Ensure "django-cors-headers" is installed
- Check that "CORS_ORIGIN_WHITELIST" includes your frontend URL
- Verify cookies are enabeld in your browser

2. "python (malloc) out of space" error
- Filter input data to a smaller geographical area
- Increase system RAM or use a machine with more memory
- Use a larger cell size to reduce the number of grid cells

3. File upload size limit
- Frontend and backend file size limit: 700MB (adjust as needed)

4. Leafleft map not displaying
- Check Internet connection (tiles are loaded from OpenStreetMap)
- Verify Leaflet CSS is imported
- Check browser console for errors
- Ensure coordinates are in [longitude, latitude] format

## Limitations

### Memory Constraints

- **Limited RAM**: Processing very large datasets (>10 million points) may require 16GB+ RAM
- **Browser Memory**: Large visualization datasets may impact browser performance
- **Recommendation**: For datasets exceeding available memory, consider:
  - Filtering to smaller geographical areas
  - Using larger cell sizes

### Browser Compatibility

- Modern browsers (Chrome, Firefox, Safari, Edge) are fully supported
- Mobile browsers have limited support for 3D visualization


## Glossary
**Cell Side**: side length of a square cell within a grid overlay in a geographical region where trajectories are recorded. When modeling a trajectory as a sentence, we need a way to uniquely identify each loaction indicated by a coordinate pair, which in our case invovles assigning a cell id to any location within that cell. 

Note that value of this field applies to generated trajectories only. Value of the same parameter in creating a matching heatmap, which defaults to 500, can be found in [geo_process](PaLMTo_App/trajectory/geo_process.py).

| ![Earth](asset/earth.png) | ![Cell Size](asset/cell_side.png) |
|:---:|:---:|
| *Earth representation* | *Cell side visualization* |

**Number of Generated Trajectories**: total number of synthetic trajectories to be generated with PaLMTo. Theoretically, this value can be any natural number. 

**Generation Method**: how synthetic trajectories should be generated using PaLMTo model. This field can only be set to one of two values: point-to-point and length-constrained. Point-to-point approach involves filling in the gap between pre-selected origin and destination points, while length-constrained method creates a trajectory by iteratively adding points to the origin until a predefined length is achieved. Refer to [^2] for a detailed explanation. 

**Trajectory Length**: length of each trajectory generated with length-constrained method. This value controls how many location points a synthetic trajectory should contain.

[^2]: Mohammed, Hayat & Nascimento, Mario. (2024). Realistic Trajectory Generation using Simple Probabilistic Language Models. 21-24. 10.1145/3681770.3698572.
